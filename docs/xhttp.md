# XHTTP / HTTP/3 安装

## 先在面板准备节点

创建 VLESS 节点，按下面填写：

| 项目 | 填写方式 |
| --- | --- |
| 节点地址 | 客户端连接的域名，直连时解析到服务器 |
| 服务端口 | 例如 443；直连时连接端口也填 443 |
| 传输 | xhttp（旧 splithttp 名称也支持） |
| TLS | 开启普通 TLS，不选 REALITY |
| server_name | 与服务器证书一致的域名 |
| flow | 留空 |
| path | 例如 /xhttp |
| mode | packet-up 可作为起点；也可按客户端能力选择其他模式 |
| ALPN | HTTP/3 只填 h3；H2 可填 h2，不要将 h3 与 h2 混填 |

面板的传输设置示例：

```json
{"path":"/xhttp","mode":"packet-up","alpn":["h3"]}
```

路径、mode、extra、XMUX、downloadSettings 等高级项在面板配置，并保存后更新客户端订阅。订阅转换器和客户端必须支持相应高级参数；服务端支持不等于所有客户端都支持。上下行使用不同 IP 时，两个入口最终必须到达同一个 XHTTP 入站实例。

## 在服务器运行向导

首次安装时选择生成配置，已有安装运行 `V2bX generate`：

1. 填写面板根地址，例如 `https://panel.example.com`，不要带后台路径。
2. 填写面板对接 API Key，输入时不显示。
3. 选择 **3. VLESS + XHTTP / HTTP/3**，填写节点 ID。
4. 向导读取并检查面板节点；协议、TLS、flow 或 ALPN 不匹配时会停止，已有配置不变。
5. 选择自动申请证书或已有 PEM 证书，按提示确认域名。

需要包含 Xray 的官方 V2bX v1.4.7 或更新版本，建议使用最新已完成构建的稳定版。脚本只下载发布包，不在服务器编译 Go。不要选择 sing-box 来运行 XHTTP。

向导结束会启动服务，等待配置中的 XHTTP 端口由 V2bX 实际监听。申请证书或监听失败时恢复向导开始前的配置；失败日志和配置保存在提示的私有目录。监听成功后仍应使用客户端验证公网连接。

## 证书和端口

推荐 HTTP 自动申请：域名解析到本机，开放 TCP 80；使用 Cloudflare 等服务时，先将记录设为“仅 DNS”。证书按域名单独存放，V2bX 负责申请和续签，TCP 80 后续也要保持可访问。

已有证书可填写完整证书链与私钥的绝对路径，例如 Let's Encrypt 的 `fullchain.pem` 和 `privkey.pem`。向导检查文件存在且可读；证书必须与面板 server_name 匹配。由原证书工具负责续签，并在续签后重启 V2bX。

H3 使用 UDP：在云安全组和系统防火墙放行面板配置的服务端口，例如 UDP 443。H2 使用 TCP。脚本会显示该节点实际需要放行的协议与端口，不会自动更改防火墙。

## 后续修改与更新

- 用户、端口、path、mode、extra 等由 V2bX 持续拉取，通常不必重新生成本机配置。
- 当前内核的监听 ALPN 使用本机选项：向导会从面板复制 ALPN。**切换 H2/H3 后重新运行向导**，并同步防火墙；单纯修改面板 ALPN 不会改变已有本机选项。
- 证书域名或路径变化也需要更新服务器证书配置。
- `V2bX generate` 会重建节点及辅助配置，并备份旧 config.json。有自定义路由或多节点配置时，先备份整个 `/etc/V2bX`，再运行向导。
- 更新使用 `V2bX update`；指定版本例如 `V2bX update v1.4.8`。安装器使用标准 ZIP 和 SHA256 校验文件；发布构建尚未完成或下载失败时保留旧程序。
- 更新会保留节点配置、证书和已有 systemd/OpenRC 服务文件，并保留上一版程序为 `/usr/local/V2bX/V2bX.previous`。如果新版进程启动失败，会尝试恢复上一版程序；协议连通性仍需客户端测试。
