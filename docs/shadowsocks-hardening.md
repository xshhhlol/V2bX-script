# Shadowsocks 兼容加固（V2bX v1.4.2）

实现涉及并列目录下的 `sing-shadowsocks`、`sing-box_mod` 和 `V2bX`。入站使用前者；sing-box 的出站客户端使用独立的 `sing-shadowsocks2`，本次不需要额外 fork 出站库。

## 面板与安装向导怎么选

已有 `aes-128-gcm` 等普通 SS 节点可以保持原加密方式。客户端和面板都支持时，才考虑选择 `2022-blake3-aes-128-gcm` 或 `2022-blake3-aes-256-gcm`；更换算法或密钥后需要更新客户端订阅。SS2022 的服务端密钥在面板配置，V2bX 从面板读取。

面板的连接地址填客户端能访问的域名或 IP。直连时连接端口与服务端口相同；有中转或映射时，连接端口填外部入口，服务端口填 V2bX 后端监听端口，并按需放行 TCP/UDP。向导配置原生 SS，不询问 TLS 证书；原生节点的混淆选无或关闭。已有插件节点需保留原来配套的服务端和客户端设置。

首次安装时选择生成配置，或已有安装运行 `V2bX generate`，依次选择 singbox、输入节点 ID、选择 Shadowsocks。TCP 优化默认开启，现有客户端无需调整。UDP 填充开关也可默认开启：仅面板实际 cipher 为 SS2022 时生效，普通 SS 自动跳过。向导显示的是“加入配置”，不是已经生效；这些选项需要 V2bX v1.4.2 或包含 SS 加固的更新版本，不能只更新脚本。

向导结束后统一保存配置并备份原文件，无需手工填写这些 JSON 字段。重新生成会重写节点配置，请保留需要继续使用的节点与自定义设置。

## 已实现

- 传统 AEAD：完整认证并解析目的地址后才登记 salt，拒绝最近的 TCP/UDP 重放和服务端响应反射。记录按密钥及 TCP/UDP 区分，多用户刷新不会清空历史。每个服务最多保存 65,536 条记录，达到容量后淘汰最早记录；它没有时间戳，不能承诺无限期防重放，也不跨进程重启或多个实例共享。
- SS2022：固定头、可变头、地址、填充全部验证后再原子登记 TCP salt，防止篡改请求提前占用合法请求的 salt。最后登记前重新检查时间戳，避免慢速提交延长有效期。
- SS2022：salt 至少保留 61 秒，覆盖整数时间戳最后一个有效秒；UDP 缓存 age 也至少为 61 秒，避免按整秒过期造成保留时间不足。只在 UDP 类型、时间戳、填充和地址验证通过后推进重放窗口。
- 多用户 UDP：传统 AEAD 的 NAT 关联同时区分用户、密钥和源地址，避免源端口被另一用户复用时沿用旧身份，或改密钥后仍用旧密钥回包；SS2022 缓存会话绑定用户密钥，拒绝身份头选择其他用户的缓存解密器，且不推进真实会话的重放窗口。
- 传统 AEAD 多用户：先验证加密长度，再为匹配用户分配完整数据读取器，避免每尝试一个用户就分配约 16 KiB；相同用户与密钥刷新时复用已有 Method。认证仍是 O(用户数)，没有变成常数时间。
- TCP 失败处理：支持读期限的连接默认使用 30 秒的握手期限，可配置为 1–300 秒；上下文有更早期限时取更早值。认证失败后读取剩余输入直到原期限、读错误或对端结束发送，减弱按加密方式固定字节数关闭的反馈。全进程最多同时处理 4,096 个未完成认证的连接：在解析任何请求前统一准入，认证成功后立即释放名额。满额时所有新连接统一拒绝，避免只对失败排空单独设置上限。资源耗尽仍会影响可用性。成功认证后清除握手读期限。不支持读期限的连接保留原行为。SS2022 仍按协议要求进行首包单次读取。
- sing-box 多用户入站：以用户名及凭据作为稳定身份，修复删除用户导致序号改变、归属错乱的问题。串行发布增删操作，失败的更新保留原用户；删除用户或替换凭据会关闭对应已登记的 TCP/UDP 连接。
- V2bX：保留既有 SS2022 订阅的 UUID 文本前 16/32 字节再 Base64 的规则；过短凭据返回错误，避免切片越界。对本来就不支持的 SS2022 ChaCha20 多用户模式提供明确错误，不影响协议库的单用户 ChaCha20。

## TCP 整形与 UDP 填充

TCP 下行在加密前重新分块，默认仅作用于开始的随机 8–16 条记录，每条目标大小随机为 512–2048 字节；不足一个目标长度时直接发送现有数据，不等待凑包，不添加应用字节，也不插入睡眠。每连接最多配置 64 条整形记录，之后恢复正常分块。初始 salt、响应头和首段数据继续合并写出。

普通 Write、批量 WriteVectorised、ReadFrom 和首包 BufferedWriter 均覆盖。修复了批量混合大小记录时的顺序问题、ReadFrom 遗漏伴随 EOF 返回的最后一段数据、短写未报错及并发首响应初始化问题。空写入不会提前发送不完整的响应头。

SS2022 UDP 启用新策略后，对各目标端口的小包使用原生 padding 字段补入随机长度填充，默认最多 256 字节。`MaxPacketSize=1280` 是整个外层 IP 包预算，计算 IP 基本头、UDP 头、SS 头、目的地址、认证标签，ChaCha20 另计 nonce；按实际回包客户端的 IPv4/IPv6 地址计算。路径中额外封装、IP 选项或扩展头需要自行预留预算，这不是路径 MTU 探测。已经超过预算的应用数据报不会因本功能被丢弃或追加填充。

UDP 新策略只适用于 SS2022。传统 AEAD 保持原格式；`UDPPadding.Enable=false` 或省略该项时，恢复原有的 DNS 小包填充策略，并非关闭历史实现的一切填充。

现有配置省略整形和填充时保留原发送策略；新的交互式配置会分别询问是否开启 TCP 与 UDP，默认开启。节点配置示例：

```json
"ShadowsocksConfig": {
  "HandshakeTimeout": 30,
  "TrafficShaping": {
    "Enable": true,
    "MinRecordSize": 512,
    "MaxRecordSize": 2048,
    "MinRecords": 8,
    "MaxRecords": 16
  },
  "UDPPadding": {
    "Enable": true,
    "MaxPacketSize": 1280,
    "MaxPaddingBytes": 256
  }
},
"MultiplexConfig": {
  "Enable": true,
  "Padding": false
}
```

V2bX 会按面板实际 cipher，仅向 SS2022 入站传递 UDP 填充选项。sing-box 直接配置使用 `handshake_timeout`、`traffic_shaping`、`udp_padding`，子字段为小写下划线形式，启用字段为 `enabled`。非法尺寸和预算会报错。

服务端开启复用支持时，普通旧客户端仍可连接。支持该功能的 sing-box 客户端可选择出站 `multiplex: {"enabled": true, "padding": true}`；或者单独选择 `udp_over_tcp: {"enabled": true, "version": 2}`。UoT v1/v2 与带填充的 h2mux 已验证，不会强制旧客户端使用它们。服务端 `MultiplexConfig.Padding=true` 会要求复用连接带填充，不能当成自动为普通连接补填充的开关。

## 兼容性验证

- 协议库原生客户端：传统 AES-128/192/256-GCM、ChaCha20-IETF、XChaCha20-IETF，以及 SS2022 AES-128/256、单用户 ChaCha20；验证 TCP 大数据双向传输和 UDP、重放、篡改固定/可变头、并发重放、响应反射、用户刷新、失败期限和 UDP 窗口污染。
- 独立 `sing-shadowsocks2` 客户端 → V2bX 真实监听端口：AES-128/256-GCM、ChaCha20-IETF、SS2022 AES-128/256，均验证 TCP 整形、原生 UDP（含 SS2022 填充）、带填充 h2mux 的多流复用及 UDP、UoT v1/v2；删除一个用户后的连接关闭、其他用户继续传输、新连接及流量归属。
- 真实回环 TCP：空输入、短输入、错误密码、篡改固定/可变头、截断、重放、无用户、过期时间戳、对端半关闭和准入满额；验证关闭结果与期限，以及正常应用读写不受握手期限影响。
- 原生 UDP 编解码：IPv4/IPv6 客户端与目的地址、域名、253 字节长域名、默认及自定义预算、临界尺寸和 65,000 字节载荷。空载荷仅验证协议编解码；上游旧版 NAT 适配器会把空数据报读成 EOF，不据此宣称端到端支持。
- 协议库、sing-box 用户管理、V2bX SS 集成均使用 Go race detector 验证。未逐一运行所有 GUI 客户端版本，也未在真实 DPI 分类器或远程节点上验证抗识别收益。

## 本地开销测量

Apple M4 / Darwin arm64 / Go 1.26.3 的内存写出基准（不是网络吞吐量或 DPI 评测）：64 KiB 载荷，默认 TCP 整形使密文字节平均从 65,706 增至约 66,066（增加约 360 字节，0.55%），写调用从 5 次增至约 15.6 次；基准耗时约 8.36 µs → 9.67 µs。记录随机，数值会浮动。

同环境下，128 字节 UDP 载荷的 SS2022 回包编码基准：关闭新策略为 186 字节密文，开启后平均约 314.4 字节；耗时约 299 ns → 434 ns。UDP 填充对小包的相对开销明显，可通过 `MaxPaddingBytes` 限制；这些数字不代表公网延迟或吞吐量。

当前账号没有打开 BPF 抓包设备的权限，因此没有实测 pcap 包长收益。真实 TCP 测试验证 socket 关闭结果，编解码测试验证记录长度及完整性；写调用或加密记录不能等同于 TCP 网络包。

## 构建与使用

在本脚本仓库运行：

```bash
bash build-ss-local.sh
GOARCH=arm64 bash build-ss-local.sh
```

输出 `output/V2bX-ss-linux-amd64`、`output/V2bX-ss-linux-arm64` 及各自的 `.sha256`。脚本通过临时模块文件使用两个本地库，不依赖 `go.work`，不改动发布用的 `go.mod`/`go.sum`。已有发布版中的 VMess 改动保留。

V2bX v1.4.2 已锁定包含这些改动的远程协议库和 sing-box 模块版本。已有节点可运行 `V2bX update v1.4.2` 更新服务端；安装脚本自动下载最新稳定版。更新并重启后，重放、失败处理和用户隔离修复自动生效，可选 TCP 整形与 UDP 填充仍由 `ShadowsocksConfig` 控制。仅更新管理脚本不会替换服务端实现。重新生成配置会备份旧文件；有自定义配置时可按上面的示例手工加入节点选项。

## 无法单靠服务端消除的特征

裸 SS 的高熵首包、上下行长度与时序、原生 UDP 数据报边界依然存在。传统 AEAD 的 salt 长度由算法决定，SS2022 也有固定结构；在没有填充字段的位置添加随机字节会破坏现有客户端；本次 UDP 只使用 SS2022 已有字段。此次没有插入私有字段、强制额外封装或改变客户端密码规则。

SS2022 没有前向保密；UUID 文本截取也不能当成同长度的均匀随机密钥。随机密钥迁移、SIP003 插件或其他外层传输需要面板订阅及客户端同步支持，不能在兼容目标下由服务端静默更改。本次工作减少部分重放及主动探测反馈，不保证裸 SS 流量不可识别。
